Customer Shareable · Google Cloud Technical Enablement

[교육 제안서] Google Compute Engine 아키텍처 심화 및 구축·운영 가이드

GCE(VM) 기반으로 핵심 워크로드를 구축·운영하는 고숙련 엔지니어 그룹을 위해, 단순 콘솔 조작이 아닌 GCP 내부 아키텍처(Under the Hood), Instance Group(MIG/UMIG), Cloud Load Balancing 구조 및 실전 운영/트러블슈팅을 다루는 맞춤형 기술 교육 제안서입니다.

1 교육 개요

과정명 Google Compute Engine 아키텍처 심화 및 실전 구축·운영 가이드
교육 대상 인프라 엔지니어, SRE, 플랫폼 / DevOps 엔지니어 등 고숙련 기술 인력
추진 배경
  • 핵심 서비스 워크로드를 GCE 기반으로 구축 및 운영하기 위한 엔터프라이즈 표준 아키텍처 수립
  • 기초 개념 설명 대신 실제 프로덕션 운영 시 직면하는 GCE 아키텍처 설계, Instance Group 무중단 운영, Load Balancer 내부 동작 원리 및 트러블슈팅 가이드 필요
핵심 달성 목표
  • GCE 구축 표준화: 머신 패밀리/스토리지(Hyperdisk)/네트워크 티어 선택, Golden Image 파이프라인, OS Login + IAP 보안 접근 체계 수립
  • Instance Group 마스터: UMIG vs MIG, Regional MIG 멀티존 분산, 무중단 배포(Rolling/Canary), Autohealing, Stateful MIG(고정 IP/디스크 보존) 운영
  • Load Balancing 내부 구조 이해: Maglev(L4) & Envoy(L7) 아키텍처, Proxy vs Passthrough 패킷 흐름, MIG 연동 시 Balancing Mode 및 502 에러 방지 튜닝
  • Day-2 운영 및 트러블슈팅: LB 레이턴시 분석, 헬스체크 디버깅, Connection Draining 검증 및 Terraform 운영 주의사항 습득

2 고숙련 엔지니어 맞춤형 설계 포인트

🔍 내부 동작 원리 중심 해부

기초적인 VM 설명은 배제하고, GCP의 Andromeda SDN, GFE, Maglev, 분산 Envoy 프록시 등 내부 아키텍처와 상태 머신을 기반으로 왜 특정 설계와 튜닝이 필요한지 심층 해부합니다.

🏛️ GCP 고유 설계 철학 & 공식 레퍼런스

Google Cloud Architecture Framework 및 공식 문서 범위(Customer Shareable) 내에서, 프로덕션 환경의 핵심인 Global VPC, Service Account 방화벽, LB Health Check와 Autohealing 분리 등을 집중 조명합니다.

🛠️ 실전 장애 대응 & 무중단 배포

단순 생성 가이드가 아니라 무중단 카나리 배포, Autohealing 복구 타임라인, 502 에러(Keep-alive 미스매치) 방지 및 로그 추적 등 실전 운영 시나리오를 다룹니다.

3 핵심 커리큘럼 모듈 및 Hands-on Lab 구성

Module 1 GCE 코어 아키텍처 및 엔터프라이즈 구축 가이드
  • Compute & Network: 머신 시리즈(C3/C4, N2/N4), gVNIC/Tier 1 대역폭, 호스트 유지보수(Live Migration) 메커니즘
  • Storage & Image: Persistent Disk vs Hyperdisk 동적 성능 프로비저닝, Golden Image(Packer) vs Startup Script 조합
  • Security Baseline: Global VPC 방화벽 설계, Metadata Server 보안, OS Login + IAP Tunneling 엔터프라이즈 접근 제어
Module 2 Instance Group 심화 운영
  • UMIG vs MIG: 아키텍처 비교, Regional MIG 멀티존 분산 알고리즘(Target Distribution Shape) 및 장애 격리
  • 무중단 배포: Rolling Update(Proactive), Canary 배포, maxSurge / maxUnavailable / minReadySec 설계
  • Autoscaling & Stateful MIG: LB Health Check vs Autohealing 분리, Graceful Shutdown, 고정 IP/디스크 보존형 Stateful MIG
Module 3 Cloud Load Balancing Deep Dive
  • Maglev vs Envoy: Pre-warming이 불필요한 이유, Proxy LB vs Passthrough LB(DSR) 패킷 흐름 및 Source IP 보존
  • L7 ALB & L4 NLB: Forwarding Rule → Target Proxy → URL Map → Backend Service 해부, Internal NLB 멀티 티어
  • LB + MIG 결합 이슈: Balancing Mode(UTILIZATION vs RATE), Connection Draining, Keep-alive 튜닝(502 에러 방지 공식)
Module 4 Day-2 운영, 모니터링 및 IaC 가이드
  • Observability: Ops Agent 메트릭/로그 수집, LB 로그 레이턴시(total_latencies vs backend_latencies) 병목 분석
  • Troubleshooting: Serial Console 디버깅, VPC Flow Logs, Connectivity Tests 기반 방화벽/라우팅 즉시 검증
  • Terraform 주의사항: Instance Template 교체 시 create_before_destroy 필수 패턴, Quota/Reservation 관리
Lab 1 보안 베이스라인 GCE & IAP

Public IP 없는 Private VM + Cloud NAT 구성, OS Login 및 IAP Tunneling을 통한 무키(Keyless) SSH 접속 및 Startup Script 검증

Lab 2 MIG 무중단 배포 & 복구

Regional MIG 배포 후 v1 → v2 Canary 및 Rolling Update 수행, 프로세스 강제 종료를 통한 Autohealing 자동 복구 타임라인 관찰

Lab 3 L7 ALB 연동 & 장애 디버깅

MIG + L7 ALB 트래픽 분할 구성, 의도적 502 에러(Keep-alive/방화벽 이슈) 주입 후 Cloud Logging 및 Connectivity Test로 원인 추적

  • 2. 실습 도구 선호도: gcloud CLI + Console 병행(기본안, 빠른 아키텍처 검증 및 디버깅 중심) vs Terraform 코드 기반 실습 병행(IaC 라이프사이클 확인 포함)
